# معماری فنی ادغام با Google Gemini و زمان‌بندی ربات
## Gemini AI Technical Integration, Bot Scheduler & Resilience

این سند معماری نرم‌افزاری اتصال به Google Gemini API، زمان‌بندی ربات صبح‌نامه، کشینگ داده‌ها، مدل‌های داده و روش‌های تست و خطایابی را مشخص می‌کند.

## ۳. جدول مدل داده خلاصه‌های هوش مصنوعی در دیتابیس

```sql
-- جدول ذخیره خلاصه‌های نمادها
CREATE TABLE ai_stock_summaries (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  stock_id UUID NOT NULL REFERENCES stocks(id) ON DELETE CASCADE,
  summary_payload JSONB NOT NULL,
  post_count_analyzed INT NOT NULL,
  model_version VARCHAR(50) NOT NULL DEFAULT 'gemini-1.5-flash',
  expires_at TIMESTAMPTZ NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_ai_summaries_stock_expires ON ai_stock_summaries(stock_id, expires_at DESC);

-- جدول آرشیو صبح‌نامه‌های روزانه ربات
CREATE TABLE ai_morning_briefs (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  brief_date DATE UNIQUE NOT NULL DEFAULT CURRENT_DATE,
  tweet_id UUID REFERENCES posts(id) ON DELETE SET NULL,
  content TEXT NOT NULL,
  tagged_symbols TEXT[] NOT NULL DEFAULT '{}',
  tokens_used INT NOT NULL DEFAULT 0,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

## ۴. استراتژی تاب‌آوری و مدیریت سقف نرخ (Resilience & Rate Limiting)

1. **مدیریت خطای سقف درخواست (HTTP 429):** در صورت دریافت خطای محدودیت نرخ از گوگل، صف BullMQ درخواست را با مکانیزم تاخیر تصاعدی (Exponential Backoff با فواصل ۲۰s، ۶۰s، ۱۸۰s) مجدداً امتحان می‌کند.
2. **عدم اختلال در عملکرد کاربران عادی:** در صورت قطعی کامل اینترنت بین‌الملل یا قطعی گوگل، پلتفرم بدون کوچک‌ترین نقصی به کار خود ادامه می‌دهد؛ کارت خلاصه‌سازی به آرامی از صفحه نماد پنهان شده و فرآیند ارسال توییت‌ها بدون هیچ تاخیری انجام می‌پذیرد.
