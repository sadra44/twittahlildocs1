# امنیت، احراز هویت پیامکی و کنترل نرخ درخواست‌ها
## Security Architecture, Mobile OTP & Rate Limiting Specifications

این سند استانداردهای امنیتی سامانه، چرخه ورود و صدور توکن‌ها، مکانیزم‌های مقابله با سوءاستفاده‌های سایبری و قوانین کنترل نرخ ترافیک (Rate Limiting) را تشریح می‌کند.

---

## ۱. چرخه حیات احراز هویت پیامکی (SMS OTP Authentication Flow)

ورود به سامانه با شماره تلفن همراه ایران (فرمت `09xxxxxxxxx`) و بدون نیاز به حفظ کلمه عبور پیچیده انجام می‌شود:

```text
[ کاربر ] ──( ۱. شماره موبایل )──► [ سرویس احراز هویت ]
                                          │
                                          ├─ استعلام کش ردیس: آیا کد فعال موجود است؟
                                          │   (محدودیت: هر ۱۲۰ ثانیه حداکثر ۱ پیامک)
                                          │
                                          ├─ تولید کد تصادفی ۵ رقمی امنیتی (CSPRNG)
                                          ├─ ذخیره در ردیس با انقضای ۱۲۰ ثانیه: auth:otp:{phone}
                                          │
                                          ▼
                                   [ درگاه پیامک ] ──► ارسال SMS به کاربر
                                          │
[ کاربر ] ◄──( دریافت کد ۵ رقمی )────────┘
   │
   └──( ۲. درج کد در اپلیکیشن )──► [ سرویس احراز هویت ]
                                          │
                                          ├─ مقایسه کد و بررسی سقف خطا (حداکثر ۳ تلاش)
                                          │   (تلاش بیش از ۳ بار = ابطال کد و بلاک ۱۰ دقیقه‌ای)
                                          │
                                          ▼ در صورت تطابق
                                   [ صدور توکن‌های JWT ]
                                   • Access Token (عمر ۱۵ دقیقه)
                                   • Refresh Token (عمر ۳۰ روز در کوکی HttpOnly)
```

---

## ۲. مشخصات توکن‌های دسترسی (JWT Token Specifications)

* **Access Token:**
  * در قالب هدر استاندارد `Authorization: Bearer <TOKEN>` ارسال می‌شود.
  * ساختار پی‌لود (Payload):
    ```json
    {
      "sub": "c1f7b820-22e3-4f9e-a89b-944a956d2994",
      "handle": "dr_sohrabi",
      "tier": "VERIFIED_ANALYST",
      "is_verified": true,
      "iat": 1728470000,
      "exp": 1728470900
    }
    ```
* **Refresh Token:**
  * منحصراً در کوکی امن با ویژگی‌های `HttpOnly`, `SameSite=Strict`, `Secure` ذخیره می‌شود.
  * نسخه هش‌شده توکن در جدول پایگاه داده نگهداری می‌شود تا با خروج کاربر (Logout) یا مسدودسازی، بلافاصله از تمامی دستگاه‌ها نامعتبر گردد.

---

## ۳. جدول قوانین جامع کنترل نرخ (Rate Limiting Rules)

برای مقابله با حملات نفی سرویس (DDoS)، بات‌های اسپمر و ثبت‌نام انبوه، قوانین زیر در لایه معکوس پروکسی (Nginx/Gateway) و با حافظه ردیس با الگوریتم پنجره کشویی (Sliding Window) اعمال می‌شود:

| قلمرو / عملیات | کلید رهگیری (Tracking Key) | سقف مجاز | پنجره زمانی | رفتار در صورت نقض قانون |
| :--- | :--- | :---: | :---: | :--- |
| **درخواست پیامک OTP** | شماره تلفن همراه | ۱ بار | ۱۲۰ ثانیه | خطای ۴۲۹ با نمایش ثانیه‌شمار معکوس |
| **درخواست پیامک OTP** | آدرس IP کاربر | ۵ بار | ۱ ساعت | خطای ۴۲۹ و مسدودسازی موقت IP |
| **بررسی کد OTP** | شماره تلفن همراه | ۳ بار | ۱۲۰ ثانیه | ابطال کد و قفل شماره به مدت ۱۰ دقیقه |
| **انتشار یادداشت (عادی)** | شناسه کاربر (`user_id`) | ۱۰ پست | ۱ ساعت | خطای ۴۲۹ با پیام: «سقف مجاز پست ساعتی» |
| **انتشار یادداشت (تحلیل‌گر)**| شناسه کاربر (`user_id`) | ۳۰ پست | ۱ ساعت | خطای ۴۲۹ |
| **انتشار نظر و پاسخ** | شناسه کاربر (`user_id`) | ۳۰ نظر | ۱ ساعت | خطای ۴۲۹ |
| **پسندیدن یادداشت (Like)**| شناسه کاربر (`user_id`) | ۱۲۰ لایک | ۱ ساعت | نادیده گرفتن درخواست‌های اضافی |
| **کوئری‌های عمومی API** | آدرس IP مشترک | ۳۰۰ درخواست | ۱ دقیقه | خطای ۴۲۹ (مسدودسازی ۵ دقیقه‌ای IP) |

---

## ۴. اقدامات ضدآسیب‌پذیری (Application Security Hardening)

1. **جلوگیری از تزریق اسکریپت (XSS Protection):**
   * تمامی متون ارسالی کاربران پیش از رندر در کلاینت یا ذخیره، با کتابخانه‌های معتبر (مانند DOMPurify) پاکسازی شده و کاراکترهای خطرناک HTML خنثی می‌شوند.
2. **سیاست امنیت محتوا (Content Security Policy - CSP):**
   * اعمال هدرهای امنیتی سخت‌گیرانه برای جلوگیری از بارگذاری اسکریپت‌های ناشناس خارج از دامنه‌های پلتفرم.
3. **رمزنگاری در حال انتقال و سکون (Encryption in Transit & at Rest):**
   * اجبار پروتکل HTTPS (TLS 1.3) و فعال‌سازی HSTS با عمر ۱ ساله.
   * رمزنگاری داده‌های حساس اسناد هویتی تحلیل‌گران در فضای ذخیره‌سازی ابری با الگوریتم AES-256.
